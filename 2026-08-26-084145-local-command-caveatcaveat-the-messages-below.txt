  What exists today

  Path: dev preset (Ninja)
  Config: Debug
  Optimized?: ❌ (except Rapier crates, see below)

  Path: release preset (Ninja)

  ────────────────────────────────────────
  Path: VS folder "x64-Release" (out/build/x64-Release)
  Config: RelWithDebInfo already!
  Optimized?: ✅
  Debuggable?: ✅

  Interesting: CMakeSettings.json already configures VS's x64-Release as
  RelWithDebInfo, and the sccache /Zi→/Z7 workaround in the root
  CMakeLists.txt:71 already covers the RELWITHDEBINFO flag vars — the config was
  clearly anticipated, there's just no preset for it and the Rust side wasn't
  included.

  What RelWithDebInfo gives you out of the box

  - C++: /O2 /Ob2 /DNDEBUG /Zi (or /Z7 under sccache) + /DEBUG link → full PDB,
    full optimization. Crucially the Release-only /GL /LTCG /OPT:REF /OPT:ICF
    flags are gated on $<CONFIG:Release> (CMakeLists.txt:29-41), so they don't 
    apply — that's what keeps it debuggable and links much faster than Release.
    Typically within a few % of Release perf.
  - Physics/Rust: confirmed in the vendored Corrosion 0.6.1 source
    (cmake/Corrosion.cmake:762) — any config except Debug passes --release to
    Cargo. So the bridge gets your [profile.release]: lto = "fat", codegen-units
    = 1. Full speed. (Rapier already runs opt-level = 2 even in Debug builds,
    so dev isn't as slow as it looks.)
  - No CRT mismatch surprises — the root already forces /MD (release CRT) in all
    configs for Rust linking.

  The gaps for "optimized but VERY debuggable"

  1. No release-debug preset — need one in CMakePresets.json
     (configure/build/test, own build-ninja-reldeb/ dir).
  2. MSVC /Zo (Enhanced Optimized Debugging) is missing for RelWithDebInfo —
     it's the flag that makes locals and line-stepping sane in /O2 code, at
     essentially zero runtime cost. (CMake's RelWithDebInfo doesn't set it by
     default.)
  3. Rust has no debug info in any optimized build — [profile.release] in
     rust/Cargo.toml doesn't set debug, so it defaults to false: no symbols for
     your own rapier_bridge code (breakpoints, stack frames through physics
     calls — all blind). One line fixes it; debug = true = step into Rust with
     locals, debug = "line-tables-only" = correct file:line stack traces only,
     cheaper to compile. Neither changes runtime codegen — it only goes into the
     .pdb.
  4. Minor behavior note: DebugOverlayService defaults off under NDEBUG
     (DebugOverlayService.hpp:139) — but it stays runtime-toggleable via the
     existing hotkey in GameApp.cpp:42, so nothing is lost. No plain assert()
     anywhere in src/, so no other behavior changes with NDEBUG.

  Everything else (PCH, sccache, raylib vendored DLL — which is already a
  release build — CPM deps, tests, architecture guards) is config-agnostic and
  works as-is.
